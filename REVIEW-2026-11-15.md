## 4. Findings and fixes (claudian-bridge)

### 4.1 Two stale characterization tests
- `a nonexistent cwd silently falls back to the default workspace`
- `cwd OUTSIDE the workspaces root is accepted` (its own comment: "KNOWN BUG — flips in M1/M2")

Cause: `resolveWorkspaceCwd` (`server.mjs:564`) now enforces `WORKSPACES_ROOT`, so `/chat` returns 400 and spawns nothing. The tests read `lastClaude()`, which returned the previous test's invocation, producing a confusing wrong-path assertion.

Fix: tests rewritten to assert HTTP 400 and no new invocation (`tests/chat.test.mjs`). The code behavior was correct.

### 4.2 Test-suite hang (real bug)
Symptom: `chat.test.mjs` never exited ("Promise resolution is still pending but the event loop has already resolved"), 60–400 s.

Bisect: only the `lifecycle and process control` block hung. A standalone repro showed `stop()` finished cleanly but the process stayed alive, held by a ref'd `Timeout`.

Root cause: the `/chat` keepalive `setInterval` (15 s) was cleared only on `req` `close` or `res` `finish`. On Node >= 20 `req` closes before the handler registers its listener, and `finish` never fires when the client aborts, so the interval leaked. In production this is a per-aborted-request timer leak.

Fix (`server.mjs`, near line 1471):

```js
res.on("close", () => clearInterval(keepaliveTimer));
```

Note: an unrelated `sleep 3600` process seen during debugging belonged to the system cups snap, not the tests. It was not touched.
